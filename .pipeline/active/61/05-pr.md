## Summary

Moves pre-game UI (name field + start button) from canvas-drawn rendering to visible HTML elements, improving accessibility and mobile touch support while maintaining visual consistency with the game's gold/dark theme.

## Changes

### `index.html`

- Moved pre-game UI elements (`#playerNameInput`, `#startGameBtn`) from hidden (off-screen) to visible inside `.canvas-wrapper`
- Added CSS classes: `.pre-game-input`, `.pre-game-btn` for styling
- Removed inline styles (`position: absolute; left: -9999px`) that were hiding the elements

### `style.css`

- Added `.pre-game-input` styles: centered positioning, gold border, dark background, focus glow effect
- Added `.pre-game-btn` styles: centered below input, gold background matching game theme, hover effect
- Added `.canvas-wrapper.game-active` state: fades pre-game UI to 30% opacity during gameplay, restores on hover
- Added `@keyframes inputShake` animation for empty name validation feedback

### `js/game.js`

- Added element reference: `const canvasWrapper = canvas.parentElement` for DOM class manipulation
- Removed unused variables: `nameFieldX`, `nameFieldW`, `nameFieldH`, `startBtnX`, `startBtnW`, `nameFieldFocused`, `shakeOffset`, `shakeStartTime`
- Simplified event handlers: removed canvas click/touch hit-testing logic (no longer needed with HTML elements)
- Removed `roundRect()` helper function and all canvas-drawn UI code (~100 lines of drawing code)
- Added touch support for pre-game input on mobile devices
- Shake animation moved to CSS class toggle (`nameInput.classList.add("shake")`) instead of JS-based offset calculation
- Added `canvasWrapper.classList.remove("game-active")` in `drawPreGameUI()` and `.add("game-active")` in `startGame()`

## Testing

- Lint passes (no new errors)
- Format applied successfully
- HTML/CSS/JS validity verified
- Pre-game UI now uses native HTML elements for better accessibility, keyboard navigation, and mobile touch support
